# nonogram-web

React/TypeScript web client for the [nonogram-app](https://github.com/chanaRoobinski/nonogram-app)
backend — generate or hand-draw nonogram puzzles, solve them on an interactive board, with hints,
undo/redo, records/history, print, zoom, and a mobile-friendly touch layout.

See `NONOGRAM_WEB_SKILL.md` (installed as a project skill at `.claude/skills/nonogram-web/`) for
the full stage-by-stage build plan, and `PROGRESS.md` for the decision log and current status
(all 8 stages complete — this is a finished MVP).

## Prerequisites

- Node.js 22+
- A running instance of the [nonogram-app](https://github.com/chanaRoobinski/nonogram-app) backend
  (for the dev server and E2E tests; unit/component tests use a mocked API and need no backend)

## Getting started

```bash
npm install
npm run dev
```

By default the client talks to `http://localhost:8000`. Start the backend there, e.g. from a
checkout of `nonogram-app`:

```bash
pip install -e .
uvicorn nonogram.api.main:app --port 8000
```

The backend must have CORS enabled for the client's dev origin (already configured on
`nonogram-app`'s `main` branch — see `PROGRESS.md` for the history of that cross-repo fix).

To point the client at a different backend URL, copy `.env.example` to `.env.local` and set
`VITE_API_BASE_URL`. Remember to delete `.env.local` before running `npm run test` — Vite loads it
for every command, including tests, and it will silently break the MSW mocks (a recurring pitfall
during development; see `PROGRESS.md`).

## Scripts

| Script | Purpose |
| --- | --- |
| `npm run dev` | Start the Vite dev server |
| `npm run build` | Type-check (`tsc -b`) and build for production |
| `npm run lint` | ESLint |
| `npm run format` | Prettier, write mode |
| `npm run test` | Vitest — unit + component tests, mocked API (MSW), no backend needed |
| `npm run test:watch` | Vitest in watch mode |
| `npm run e2e` | Playwright — full browser E2E, **requires a live backend** at `VITE_API_BASE_URL` |
| `npm run generate:api-types` | Regenerate `src/api/generated/schema.ts` from an OpenAPI source |

## Regenerating API types

`src/api/generated/schema.ts` is generated by [`openapi-typescript`](https://openapi-ts.dev/) and
must never be hand-edited. Two ways to regenerate it:

- **From the checked-in snapshot** (default, no backend required):
  ```bash
  npm run generate:api-types
  ```
  This reads `openapi-snapshot.json` at the repo root. Re-export that file from the backend
  whenever its API schema changes (from a Python shell in `nonogram-app`:
  `json.dump(app.openapi(), open('openapi-snapshot.json', 'w'))`), then re-run the script above and
  commit both files together.
- **From a live backend**, if you'd rather generate straight from a running server:
  ```bash
  npx openapi-typescript http://localhost:8000/openapi.json -o ./src/api/generated/schema.ts
  ```

## Testing

- **Unit/component tests** (`npm run test`) run under Vitest + jsdom + React Testing Library. All
  network calls are intercepted by [MSW](https://mswjs.io/) (`src/mocks/`) — no backend needed, and
  `onUnhandledRequest: 'error'` means an un-mocked request fails the test loudly rather than hitting
  the real network.
- **E2E tests** (`npm run e2e`, Playwright + chromium) run against a real running backend and cover
  full user flows: generate → play → hint → check → win, manual puzzle creation, touch drag-paint,
  keyboard-only play, accessibility (`@axe-core/playwright`), error states (network/route
  interception), and difficulty/size variations. Start the backend first (see above) and set
  `VITE_API_BASE_URL` if it's not on the default `http://localhost:8000`.
- CI (`.github/workflows/ci.yml`) runs both: a `test` job (lint, unit/component tests, build) and an
  `e2e` job that checks out `nonogram-app` alongside this repo, starts a real `uvicorn` backend, and
  runs the full Playwright suite against it.
